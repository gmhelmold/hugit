TL githugr · ~5 min Passo 1 — Re-deployar o motor

Isso reconstrói o motor com o código de hoje e acende tudo que é baseado nos dados (os reads novos, paridade de verbos) + reconfirma o login. É só ops, não precisa de nada novo — e é a mão do TL do githugr, não tua.

⤵ Tudo isto é na pasta ../githugr (NÃO no hugit).

1
Abre o arquivo engine.wrangler.jsonc e acha a linha ENGINE_CACHE_BUST. Troca o valor por qualquer texto novo: 
"image_vars": { "ENGINE_CACHE_BUST": "2026-06-18-w3w5-main" }
💡 Por quê? O Cloudflare guarda a imagem em cache. Se você não mudar nada aqui, ele acha que é igual e não reinicia o servidor — aí seu deploy "funciona" mas o código novo nunca sobe. Mudar esse texto força um container novo.
2
No terminal, dentro de ../githugr, roda: 
npx wrangler login          # só na 1ª vez (abre o navegador p/ logar na Cloudflare)
npx wrangler deploy -c engine.wrangler.jsonc
💡 O que faz? Reconstrói o motor (hugit-serve) a partir do código atual e sobe um container novo na Cloudflare. Demora alguns minutos (ele compila Rust). No fim ele imprime que deployou.
3
Confere que subiu — cola no terminal: 
curl -sS https://engine.githugr.com/readyz
✓ Esperado: responde ready (ou um JSON de OK).
⚠️ Se o deploy falhar dizendo erro de compilar/dependência, me chama — provavelmente é infra (o runner tem isso ~37% das vezes) ou algo que eu resolvo rápido.

TL do githugr Passo 2 — Ligar o git clone + blob/edit

Esses três leem arquivos de um repositório git dentro do container. Mas o container de hoje é mínimo (não tem o programa git) e lê os dados do R2, não de um repo. Então eles não acendem só com o Passo 1 — precisa mexer na "receita" do container (engine.Dockerfile do githugr).

Por que não é você? Esse arquivo mora no repo do githugr e eu tenho uma trava (fence) que me impede de mexer no repo dos outros. Eu já escrevi a receita EXATA — é só o TL do githugr aplicar (3 coisas no engine.Dockerfile):

  1. Botar o programa git no container (hoje não tem).
  2. Botar uma cópia do repo hugit dentro da imagem (ex.: em /app/repo).
  3. Apontar HUGIT_SERVE_GIT_DIR=/app/repo + dar deploy de novo (igual o Passo 1).

A receita detalhada (com o diff exato) está na versão .md deste doc, seção "STEP 2".

✓
Depois do Passo 2, o teste final (o que prova tudo): 
git clone https://engine.githugr.com/hugit /tmp/hugit-clone
✓ Esperado: clona de verdade, com o histórico real. Isso é o git clone funcionando ao vivo pela 1ª vez. 🎯
