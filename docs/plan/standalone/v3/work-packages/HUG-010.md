# HUG-010 — Status de shell separado do status de captura

**Estado:** planned; **owner:** C; **fase:** A; **prioridade:** first_slice.

**Dependências:** HUG-003

**Congelamento de runtime requerido:** false

**Revisões:** AR-08, AR-15

**Contratos vinculados:**
- P00@3.0 — sha256 `5d737267087e24bbcca9548488c719f4cca46fa3435a0ccf31b7b98696fde5cc`

## Prontidão

Todos os predecessores possuem evidência integrada e interfaces versionadas compatíveis.

Owner C aceita write-set exato e budget B-CORE; HUG-001 distingue arquivos existentes dos novos.

Os casos P/N/Q/R e os oráculos estão especificados antes do dispatch; fixtures e testes executáveis são entregues pelo próprio pacote ou predecessor. Documentação/descoberta usa oráculos de artefato, não um falso bug de runtime.

Qualquer dado de fonte ainda não observado bloqueia o consumidor; descobrir no pacote predecessor, sem inventar payload.

Usar a especificação aprovada desta revisão; descobertas/contratos e contenções de baseline produzem as pré-condições do freeze, sem ativar implicitamente o runtime v2.

## Unidades verificáveis

1. **HUG-010.S1** — Preservar exit 0..255 do child concluído no modo pipe; sucesso do recorder não muda falha do trabalho.
2. **HUG-010.S2** — Sem child lançado: erro do Hugit=125; timeout=124; sinal POSIX representado em JSON e código 128+signal quando aplicável. Colisões numéricas são distinguidas por exit_origin.
3. **HUG-010.S3** — Falha de capture mantendo child success mantém exit do trabalho mas recorder_status=partial/failed; modo explicito --require-evidence falha quando não há evidência exigida. Hooks Git observacionais continuam fail-open.
