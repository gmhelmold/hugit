squad C · M · sonnet · 70k · branch: wp/C4

## Charter
Build the derived-file regeneration drivers v0: declared-derived files
(lockfiles, codegen, snapshots) are always regenerated from sources, never
text-merged. Cargo.lock + pnpm-lock are the first drivers, wired into B4's union
builds. Regeneration is deterministic; failure fails CLOSED; the merge codepath
is provably never entered for derived-classified paths.

## Implementation notes (every fork PRE-DECIDED)
- **Drivers: Cargo.lock + pnpm-lock FIRST** — implement these two
  lockfile drivers now; codegen + snapshot classes are exercised per ④ but the
  v0 concrete drivers are the two lockfiles.
- **Regenerate, never merge:** for any derived-classified path the regeneration
  command runs from sources; the text-merge codepath is structurally unreachable
  for those paths (⑥ proves it is never entered). Hand-edits to derived files are
  discarded + regenerated (④).
- **Determinism:** regen is deterministic — same sources → same bytes. The ⑥
  fixture deliberately makes a clean text-merge yield different bytes; the
  regenerated bytes win.
- **Fail CLOSED (⑤):** if the regen command itself fails (e.g. unsatisfiable
  constraints), the union build fails CLOSED with a clear status — never a
  silently or partially merged derived file. (§9 lock 5 degradation invariant.)
- Runs on the C2/C3 runner (container-per-job on the Hetzner box) via `clw run`;
  C4 does not own the runner — it owns the drivers the runner invokes.
