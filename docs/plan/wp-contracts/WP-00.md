## Owned acceptance
WP-00 has no decomposition-table acceptance items; its red→green set is the
contract suite itself. The 15 frozen contracts (decomposition §1 — the v1 set
of 10 plus the 5 `(+)` additions) MUST each ship as: a Rust type, a generated
JSON Schema, and a golden serde round-trip test (serialize→bytes→deserialize
byte-identical against a committed golden fixture). The 15:

1. **CheckDef** — a check-as-code definition: `{def_digest, command, inputs[],
   toolchain_ref, env_manifest, glob_set[]}`. The `def_digest` is the canonical
   digest over the definition body (the second axis of the memo key).
2. **CheckResult** — memo of `check(tree_hash, def_digest, toolchain_digest)`:
   `{memo_key, tree_hash, def_digest, toolchain_digest, exit, artifacts[(path,
   digest)], stdout_ref, stderr_ref, duration_ms, runner_ref, produced_at}`.
   Bit-identical across phases (X9①).
3. **DiagnosisObject** — bounded structured diagnosis (never a raw log dump):
   `{culprit_ref, diff_vs_green_ref, suspect_targets[], bisect_path[],
   size_bytes (asserted bounded)}` (B5④).
4. **IntentSidecar** — PR-attached intent metadata: `{intent_id, charter,
   acceptance[], context_ref, authoritative:false}` — non-authoritative,
   never gates landing (B6④).
5. **RunnerLease** — `{lease_id, principal_chain, path_set[], expiry,
   net_policy, tmp_root, state ∈ {held, expired, crashed, released}}`.
6. **FenceManifest** — claim-filtered sparse materialization manifest:
   `{path_set[], deny_default:true, materialized[(path,digest)]}` — sparse
   materialization IS the fence (whitepaper §9.1).
7. **EventRecord** — one append-only hash-chained event:
   `{seq, prev_hash, this_hash, kind, principal_chain, payload, recorded_at}`.
8. **VerdictObject** — `{intent, tree_hash, lens, model, prompt_digest,
   verdict ∈ {APPROVE, FIX-FIRST, REJECT}, claims_checked[], evidence_refs[]}`.
9. **QueueApi** — landing-queue surface: enqueue/state/union-result/seal types
   `{landable[], batch_id, union_tree, order_index, state, minimal_failing_pair}`.
10. **AppWebhooks** — GitHub App ingest/ack surface: signed-event envelope,
    ack-receipt, and the Checks-API write-back request/response types.
11. **ShadowPolicy** `(+)` — `{cadence, budget, optin}` (decomposition §1).
12. **AttentionRank** `(+)` — `{policy, blast_radius, confidence}` — the
    composite ordering inputs for the attention queue.
13. **ExportSchema** `(+)` — versioned, machine-validatable export envelope:
    `{version, object_classes[], redaction_manifest}` (E5③/⑥).
14. **AttestationChain** `(+)` — `{tree, def, runner, model, principal, sig}` —
    the full provenance chain (whitepaper §9 provenance).
15. **RegenGate** `(+)` — `{optin_scope, repass, indep_verdict}` — the
    regenerative-rebase promotion gate (decomposition §1, D12).

Green = all 15 types present, all 15 JSON Schemas generated and committed,
all 15 golden serde round-trips byte-identical.

## Implementation notes
Every fork pre-decided:
- **Crate name & path:** `hugit-contracts` at `crates/hugit-contracts/`.
- **Serde:** `serde` + `serde_json`, all structs `#[serde(deny_unknown_fields)]`,
  field order canonical (golden bytes are order-sensitive).
- **Schema:** derive `schemars::JsonSchema`; emit one `.json` per type under
  `schemas/`; a build-time test asserts schema ↔ type drift = 0.
- **Memo key (load-bearing, frozen here):** `memo_key =
  H(tree_hash ‖ def_digest ‖ toolchain_digest)` (whitepaper §6.2). All three
  axes are first-class fields on CheckResult; `H` = SHA-256 over the
  length-prefixed concatenation `LP(tree_hash) ‖ LP(def_digest) ‖
  LP(toolchain_digest)` (4-byte BE u32 length prefix per field, lowercase-hex
  UTF-8 inputs, struct field order). Single-sourced in
  `hugit_refstore::compute_memo_key`; spec on `CheckResult::memo_key`.
- **CheckResult bit-identity (X9①):** canonical serialization is deterministic
  (sorted maps, fixed field order) so the phase-B memo equals the phase-D
  evidence byte-for-byte.
- **Hash chain (EventRecord):** `this_hash = H(prev_hash ‖ kind ‖ principal_chain
  ‖ payload ‖ seq)`; genesis `prev_hash` = **64 ASCII `'0'` characters** (the
  literal hex-zero string, not 32 zero bytes). Byte-exact framing is single-
  sourced in `hugit_refstore::compute_this_hash` and spec'd on
  `EventRecord::this_hash`; emitters call that fn, never re-transcribe.
- **No logic, only types + schemas + golden tests.** This crate has zero
  runtime behavior beyond (de)serialization.
- **Frozen-on-seal:** after SEAL, edits require an orchestrator waiver; downstream
  WPs build against these stubs.
